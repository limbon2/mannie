## Intent

The owner wants agents to navigate live pages, press buttons and complete forms in a browser that the owner watches and uses beside the conversation. The pane shows the real page, which the agent drives through the same tab. Agents can sign in with a saved site credential after the owner approves it for the conversation.

## Behavior

- The Browser plugin starts off. It works on Windows, where the Microsoft Edge WebView2 runtime that Mannie already needs renders the pages. On other systems the plugin does not start, and the Plugins page says that it needs Windows.
- A conversation has its own browser session, cookies and storage. Browser tabs open in the shell's side-panel tab strip. Each panel shows its tab's live page at the panel's size. The owner uses Take over and Resume agent to switch control, and an agent can ask for control while the owner has it. The Browser toolbar menu opens live tabs and creates new tabs. The tab strip’s X hides a pane, and End session closes all live tabs and clears session data. Type an address and press Enter. A hostname without a scheme uses HTTPS.
- Under agent control the page takes no input from the owner. In takeover the owner clicks, scrolls, selects and types in the page itself, and its context menu and browser keys work without save, print, downloads and DevTools. Clicking the page or pressing F6 from the pane moves focus into the page. F6 or Tab past the page’s ends moves focus back to Mannie.
- The page hides while one of the app's dialogs, menus, selects or popovers is open, and the pane shows a still of it there. A tooltip over the page is cut out of it.
- The live tab shows an agent cursor at the points where the agent clicks, drags and scrolls. A press briefly highlights the point. The cursor accent and click highlight use Mannie's primary color for the active light or dark mode. The cursor disappears after a short pause and when the owner takes over or the pane hides.
- A line under the page says what the agent last did: a click, a fill, a choice, a key or a scroll.
- The owner can allow an exact origin for the conversation and revoke it in the conversation permissions. The grant covers observations and interactions at that origin, including localhost and intranet sites. A request to another origin fails at once, and after the owner allows it the browser sends it again. A site can load its ordinary resources and make background requests.
- To open an HTTPS site with a self-signed certificate, get its SHA-256 fingerprint from the site's administrator or server configuration. Open **Settings > Browser**. Under **Trusted hosts**, select **Add trusted host**, enter the hostname and fingerprint, and choose **Save trust**. Then retry the address. Trust covers the exact hostname and certificate across tabs and HTTPS ports. Saved trust works in other Browser conversations and after restarting Mannie. Agent access still requires approval for each origin.
- Browser keeps one saved fingerprint per hostname. To remove trust, select **Forget** for the entry in Settings. This ends sessions that allowed that certificate at that hostname. To save a replacement, forget the old entry and save the replacement's verified fingerprint.
- Browser ends the whole session five seconds before the earliest certificate it allowed expires, which closes its tabs and connections. Browser refuses to allow a certificate with five seconds or less left.
- Under **Site credentials**, choose **Add site credential** to save a password or code for an exact HTTP or HTTPS origin, including any port. The setting applies across sessions and restarts. An agent observing the approved origin sees a label and reference. The first fill with that credential asks for approval in that conversation. Revoke the grant in Conversation Permissions or remove the credential in Settings.
- The agent can read an outline and page text, request a screenshot, follow links, scroll, press keys, drag to sort lists and move items, and interact with forms. Drag and drop works in the page for the owner as in any browser. The outline includes checkbox states when available. The agent can batch element clicks and observe once after the batch. A stale or ambiguous target stops the batch. After the owner used a tab in takeover, the agent gets no screenshot of that document until the tab navigates.
- A point click or drag uses the image pixels and revision of a screenshot returned by the latest observation. The screenshot reports its JPEG dimensions. A later text-only observation supersedes the screenshot. If a point target is stale, the agent requests a fresh screenshot and chooses the point again.

## Fit

The plugin registers browser tools and a conversation side panel. The desktop's browser service hosts each session in a WebView2 environment of its own, checks site approvals, and places the native pages over the pane. The plugin uses generated IPC, the SDK's floating-layer tracker and existing tool image results. The related ADRs define the browser's trust boundary, site approvals and certificate exceptions.

## Design

The pane follows the conversation's status through the channel `browser_follow`; that subscription is the lease of the session's native pages, so they hide when no pane follows the conversation and when the app page loads again. The viewport is a placeholder that `utils/browser-surface.ts` measures and reports with `browser_place`, with the rules of `utils/browser-geometry.ts` for overlays. While an overlay hides the page, `browser_still` gives the pane a still image, which never reaches a model. `browser_focus` moves the keyboard into a page, and the status says when focus left a page, so the pane can put it on its own controls.

The agent cursor is drawn by Mannie in the tab's native window. It follows the viewport coordinates of the agent's pointer input at the page's display scale. Page content and browser screenshots contain only the page.

Agent tools use the same session through the host's browser service. The service passes each agent operation through the runtime's approval flow. Screenshots use the existing tool image result. Session files and protected values already entered into pages are cleared when the session ends. Saved values live in the master’s OS credential store. SQLite holds their metadata, certificate trust, changes to both, and the conversation’s origin and credential grants. The service checks each credential grant and the live target before protected dispatch. A denied or removed credential cannot be used to fill a field. The Windows certificate store needs no change.

## Acceptance

[V13](../../../docs/roadmap/milestones.md#4-validations) checks the browser and its approval boundary on Windows. It covers live forms and sign-in, redirects, popups, stale targets, owner takeover, teardown, credential redaction and saved certificate trust.

- The driver's tests use a scripted host on every system: `cargo test --locked -p mannie-tools --lib browser`.
- The real-engine tests use WebView2 and loopback sites: `cargo test --locked -p mannie-desktop-core --lib real_webview2 -- --ignored --test-threads=1`.
- The desktop test `plugins/browser/tests/e2e/browser.test.ts` checks that the page follows its placeholder, hides under dialogs, takes the keyboard with F6, refuses owner input under agent control, comes back after the app reloads, shows the agent cursor at two click targets, clears it on takeover, and runs the agent flows.
- The same desktop test uses loopback HTTPS sites to check that the owner can add an exception and retry, that agent origin approvals stay separate, and that trust survives new sessions, conversations and app restarts. It verifies that forgetting an entry or reaching the certificate cutoff closes affected connections. Credential tests check persistence and grants independently of origin access.
- By hand: open an HTTPS site that Windows already trusts, browse, type, scroll, select and play a video; drag the splitter; use the context menu and browser keys; take over and resume; let an agent work with the pane closed, the window minimized and in the tray; try a download, a drop from Explorer and a print; quit while an approval is pending, then confirm that no WebView2 process of the session and no `session-*` folder remain.

A page's own `window.print()` still opens the print dialog in takeover and under agent control: WebView2 has no setting that refuses it, and refusing it from the page would need a script that Mannie injects, which ADR-0064 rules out. The print key and the context menu's Print item are off.
