## Intent

Show the owner the repository that the agents work in, beside the conversation, and let the owner inspect history, diffs, branches, stashes, blame and code search or take common Git actions without leaving Mannie.

## Behavior

- A conversation in a repository's project has a Git control in its toolbar with the branch name and compact badges for uncommitted and conflicted files, which opens the Git side panel for the conversation's project. The control updates live through `follow_repository` as well as on conversation and turn changes. A "Open Git panel" command in the command palette opens the same panel for the active conversation's project. Where the project is no repository, or cannot be read without asking, the toolbar shows nothing of it.
- The panel is registered with `hideHeading: true` so the repository name appears once in the side panel tab without a duplicate heading in the panel body.
- The panel header shows an interactive branch switcher (searchable list of local branches, remote branches, and a "Create branch" action), an explicit unborn branch label ("On `<branch>`" with a "No commits yet" badge) when the repository has no commits, compact ahead and behind counts, Fetch/Pull/Push controls when remotes exist, Stash/Mention controls, and Refresh. When an operation (merge, rebase, cherry-pick, or revert) is in progress, an operation banner shows the current step with Continue, Skip, and Abort controls.
- Its tabs:
  - Changes: an inline commit box (message input, Amend toggle, Commit button, and Ctrl/Cmd+Enter submit), a filterable file list with Tree (compressed single-child directory chains) and List views, status badges, inline `+N -M` line counts, and folder-level or per-file stage, unstage, discard, blame and file history actions. Selecting any file, including an untracked file (which synthesizes an added-lines preview with symlink containment, binary detection and a 256 KiB cap), opens a diff viewer with Unified/Split toggle, word-level intra-line highlights, Ignore whitespace toggle, previous/next file navigation, Copy path, and per-hunk Stage, Unstage and Discard actions.
  - Graph: a topological commit graph (`git log --topo-order`) with an inline SVG lane diagram (vertical tracks, branch and merge curves, hollow merge rings and semantic lane colors), a scope selector (Current branch, All branches, Reflog), an expandable search and filter bar (message query, author, path, `-S` pickaxe, merge filter and first-parent only), non-clipping ref badges, pagination ("Show more"), and a responsive split commit inspector with full message, author/committer metadata, parent jumps, changed files, Mention in chat, and Checkout, Create branch, Create tag, Cherry-pick and Revert actions.
  - Branches: a searchable explorer with Local branches (two-line rows with ahead/behind pills, Checkout, Merge, Rebase, Rename, Compare, Mention and Delete actions), Remote branches grouped by remote, Tags sorted newest-first with Create and Delete actions, Stashes with an interactive diff preview and Apply/Pop/Drop actions, Worktrees, and credential-redacted Remotes with per-remote Fetch.
  - Compare: base and head ref selectors (including `WORKTREE` for working tree changes), `...` (merge-base) and `..` (direct) modes, a swap button, and tabs for Changed files (with full diff), Ahead commits and Behind commits.
  - Inspect: a file picker and optional revision input with three modes: interactive Blame (age heatmap gutter, author/hash/date columns, click-to-open commit popover with Jump to graph and Mention in chat, plus Ignore whitespace and Follow moves toggles), File history (`git log --follow` with commit selection), and Code search (`git grep` with case-sensitive, regex and path filters).
  - Conflicts, shown while an operation is in progress or a file is conflicted: per-file resolution (Use current, Use incoming, Use base, Keep both, Keep/Delete for delete conflicts, Mark resolved) and per-hunk resolution with an Apply hunk choices action. The tab hides once conflicts clear and the panel returns to Changes.
- The panel reads the repository again after each of the plugin's own changes in a repository (from agents or panel actions), on Refresh, and every 15 seconds while it shows. After a read fails, it waits twice as long before the next read, up to 2 minutes. Each read also refreshes opened tabs, and reloads the commit graph from its first page when HEAD moved.
- A value that shows stays while it is read again, and a read that fails keeps it, with what failed above it.
- A repository whose git folder lies outside the project shows that Mannie needs the owner's permission to read it, which "Allow for this project" on an agent's request gives.

## Design

- Read commands of the plugin, each taking the project's ID and never a raw host path:
  - Existing commands kept backward-compatible: `repository_overview` (extended with `remotes`, `stagedStats`, `unstagedStats`, and `--untracked-files=all`), `repository_history`, `repository_branches`, `repository_commit`, `repository_file_diff` (extended with `ignoreWhitespace` input and `untracked`, `binary`, `truncated` output flags), `repository_conflicts`, and the channel `follow_repository`.
  - Added read commands: `repository_history_query`, `repository_refs`, `repository_stash_show`, `repository_compare`, `repository_blame`, `repository_tree`, and `repository_grep`.
  - Each runs git only to read, with the project's folder and git folder checked as a model's reads in that project ([ADR-0038](../../../docs/adr/0038-let-plugins-run-installed-programs-in-the-owners-projects.md), decision 10).
- Owner action commands: `repository_action_preview` and `repository_action_run` ([panel actions](panel-actions.md), [ADR-0078](../../../docs/adr/0078-let-plugins-run-installed-programs-for-owner-actions.md)).
- Errors: `project_not_found`, `not_a_repository`, `bare_repository`, `git_missing`, `git_too_old`, `dubious_ownership`, `read_not_allowed`, `write_not_allowed`, `unknown_commit`, `locked`, `timed_out`, `repository_changed`, `already_run`, `invalid_argument` and `git_failed`.
- The panel's state lives in `ui/state/git-repository.svelte.ts`: each value keeps only its newest read through generation counters, a new watch ends the one before it, and pure helpers live in `ui/utils/` (`git-graph.ts`, `git-word-diff.ts`, `git-tree.ts`, `git-format.ts`).

### Loading, empty and error states

| View      | Loading                                                        | Empty                                                        | Error                         |
| --------- | -------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------------- |
| The panel | Placeholders, and "Loading the repository…" for screen readers | "The project's folder is not in a git repository."           | What failed, with "Try again" |
| Changes   | The panel's                                                    | "Nothing to commit: the work tree and the index match HEAD." | The panel's                   |
| A diff    | A placeholder                                                  | "No changes in this file." or binary file notice             | What failed, with "Try again" |
| Graph     | A placeholder                                                  | "No commits match the active filters." or no commits yet     | What failed, with "Try again" |
| A commit  | A placeholder                                                  | "Choose a commit to see its changes."                        | What failed, with "Try again" |
| Branches  | A placeholder                                                  | "No matches." or empty section message                       | What failed, with "Try again" |
| Compare   | A placeholder                                                  | "Choose two refs and run Compare." or no differences         | What failed, with "Try again" |
| Inspect   | A placeholder                                                  | File prompt, no blame lines, no file history or no matches   | What failed, with "Try again" |
| Conflicts | A placeholder                                                  | "No file is conflicted."                                     | What failed, with "Try again" |

## Acceptance

- Rust integration tests against real git repositories (`plugins/git/crates/mannie-git/src/panel.rs`) covering untracked and binary previews, all read commands, owner action confirmation gates, stale-state refusal, duplicate operation idempotency, discard snapshots, tags, and conflict resolution.
- Vitest tests for the layout, word-diff, tree, and formatting utilities, for `RepositoryPanel` state (`plugins/git/tests/ui/state/git-repository.test.ts`), and for the panel and cards (`plugins/git/tests/ui/components/`).
- End-to-end tests in `plugins/git/tests/e2e/git.test.ts` with axe accessibility checks in both themes.
