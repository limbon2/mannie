## Context

- On 2026-10-22 the owner reviewed the conversation view and asked for three changes. The toolbar's "Child agents", "Commands", "Full access" and export button collapse into a menu behind a button with vertical dots, and full access and the context meter go to the bottom, into the message box. Asked about this ADR, the owner kept the Git plugin's button where it is: "git stays where it stays" ([D41](../roadmap/milestones.md#5-decisions)). The message box is redesigned after the composer of ChatGPT: one framed field with the text on top and a row of buttons below it. The header's own menu of Rename, Compact now and Delete goes away, since the conversation list renames and deletes and the context meter compacts; that part needs no ADR and is done.
- [ADR-0026](0026-add-conversation-controls-back-for-child-agents.md) decided that conversation controls render in the toolbar, before the context meter (decision 3), each as a compact button or menu (decision 4). The core registers four controls, and the plugin Git registers a fifth, `git.control`, which names the current branch, through the SDK's slot catalog ([ADR-0034](0034-build-plugins-on-a-plugin-sdk.md), decision 11). Moving the controls changes the slot, and slots change only by addition ([ADR-0002](0002-grow-through-extension-points.md)).
- A control of the toolbar renders a button. Inside a menu, a button breaks the menu's keyboard navigation, so a control has to know where it renders.
- [ADR-0041](0041-let-agents-run-commands-in-the-background.md) relies on the toolbar to keep running background commands visible (threat T-52). Inside a menu, the count of running commands would be hidden.
- The message box belongs to chat. It already shows the buttons of image sources ([ADR-0033](0033-let-plugins-attach-images-to-the-owners-messages.md), decision 7), and the installed shadcn-svelte components include `input-group`, whose text area with a row below it is the documented pattern for such a field.

## Decision

1. A conversation control's entry gains an optional `place`: `toolbar`, `menu` or `message-box`. `toolbar` is the default and keeps ADR-0026 as it was, so a control that names no place works without a change.
2. The toolbar of a conversation ends with a menu, "Conversation actions", behind a button with vertical dots. A control of the place `menu` renders entries of that menu with the dropdown menu components that the SDK re-exports: an item, a checkbox item, or a submenu that lists its things. It renders nothing when it has nothing to offer, and the menu says so when no control offers anything. The menu lists its controls by their order.
3. A menu control's entry may give `running`, a function of the control's props that says how many of its things work, such as running commands or working child agents. The menu's button shows the sum as a badge and says it in its name, so running work stays visible in the toolbar.
4. The message box of an open conversation shows the controls of the place `message-box` in the row below its text, after the buttons of the image sources, as compact buttons. The message box of a new conversation shows none, and a read-only conversation has no message box.
5. A control's props gain `opener`: the element that the focus returns to when a side panel or a dialog that the control opened closes. A menu control receives the menu's button, since its own item is gone once the menu closes. A control of the toolbar or the message box receives none and passes its own button, as before.
6. The core's controls move. "Child agents" and "Commands" become submenus that keep their lists, their states and their counts, the export becomes the item "Export conversation…", and "Full access" becomes a control of the message box. The Git plugin's control names no place and stays in the toolbar, where its branch stays in view, so the plugin does not change. Chat moves the context meter into the message box, before Send; a read-only conversation, which has no message box, keeps it in its toolbar.
7. The message box becomes one framed field, built from `input-group`: the text on top, and below it the row of buttons, with the image sources and the message-box controls at its start and the context meter and Send, or Stop while a reply runs, at its end. It stands at the transcript's width. The chips of the message's images and mentions, the errors and the hint about the keys stay below the field.
8. The SDK's slot catalog carries the new fields and props. The registration tests cover each place with fake entries.

## Consequences

- Positive: the toolbar holds the profile menu, the controls that the owner wants in view, such as Git's branch, and one menu for the rest, and the message box carries what concerns the next message: full access, the context and the images. Controls that name no place keep working.
- Negative: child agents and commands are one step further away, and their counts share one badge. The slot's type grows by two optional fields and its props by one.
- Risks: a menu control that renders anything but menu entries breaks the menu's keyboard navigation. Menu controls are reviewed like other slot components, and the end-to-end tests open each one with axe in both themes.

## Alternatives considered

| Option                                              | Why not chosen                                                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| A popover that lists the controls' buttons          | A list of buttons is no menu: no arrow keys, each control's own menu opens from inside a popover, and the export button has no visible name |
| Every control renders menu entries, without a place | Breaks controls written for the toolbar, a plugin's included, which ADR-0002 rules out                                                      |
| A second slot for the message box                   | It repeats the entry, the props and the registration of the slot that exists; one field is smaller, and the controls stay in one place      |
| No count on the menu's button                       | Running commands and working child agents would show only once the owner opens the menu, which weakens T-52                                 |

## Validation

Decided by the owner (D41). The registration tests pass with fake entries for each place, and the end-to-end tests of child agents, background commands, export and full access open their controls from the menu and the message box, and Git's from the toolbar, with axe in both themes and the pseudo-locale.
