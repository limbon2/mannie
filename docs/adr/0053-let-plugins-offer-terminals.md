## Context

- The owner wants terminals as a plugin ([decision D45](../roadmap/milestones.md#5-decisions)): "A terminal that can be opened in a sidebar, can be integrated with workers and ssh plugins (so that i can execute commands on a worker machine or via ssh host directly)". The owner types in them as in any terminal, agents run commands in them and point the owner at the output that a reply relied on, and the owner points an agent at a command and its output. The owner later asked that terminals cause no lag on low-end PCs and laptops.
- The owner's answers of 2026-10-30 (D45):
  - Version 1 opens terminals on this machine and on the hosts of the SSH plugin. Terminals on a worker's host become an idea, since they need an ADR that supersedes ADR-0015 d2 in part: the master never runs tools on a worker's host (D5).
  - Terminals open as tabs of the side panel area beside the conversation. Each belongs to the conversation that opened it (D18), and only that conversation's agent uses it.
  - An agent reads only two things from a terminal: the output of the commands that it ran, and what the owner mentions.
- The design rules this out today:
  - The SDK has no service for pseudo terminals. The supervisor has modes for commands, background commands, programs and servers, and none of them attaches a pseudo console (`crates/mannie-tools/src/supervisor/`), although ADR-0014 d1 expects it to start terminals too. No lock file holds a crate for pseudo terminals or terminal emulation.
  - Only core modules consume extension points, and only the core provides services, so no plugin reads another plugin's contributions (ADR-0034 d5 and d6). The SSH plugin can offer its hosts only through a point that the core consumes, and a terminal plugin can reach them only through a service of the core.
  - `ToolAccess` has four kinds and `Access` six, and none of them covers a command typed into a shell. The rules live in three tables, `tools_rules`, `tools_remote_rules` and `tools_program_rules`.
  - What the owner types would reach a shell without the policy. ADR-0004 d2 rules this out for every command of the webview, and ADR-0036 d9 lets a plugin command reach a registered host only to read its key or test its login.
  - D11 asks for an ADR before a terminal emulator joins the UI, and a plugin's UI cannot add an npm package: the SDK adds it to the app and re-exports it (ADR-0034, ADR-0035 d7).
  - A palette command has no key (ADR-0020 d2), and the shell binds only `Ctrl+K`, `Ctrl+,` and `Ctrl+B`.
- Facts of this repository, verified on 2026-10-30:
  - A plugin tool returns one final `ToolResult` and cannot stream progress. Plugin channels go one way, from Rust to the UI, in batches at most every 16 ms with a queue of 4,096 items, and a batched channel sends the first message after a pause at once (`apps/desktop/core/src/ipc/channel.rs`), so batching adds no delay to a keystroke's echo. The UI sends data only through commands, at most 64 KiB for each input by default.
  - A command with metacharacters gets only Allow once and Deny.
  - A side panel's kind and argument are fixed, at most 8 tabs are open, and opening another conversation closes them ([ADR-0025](0025-add-side-panels-to-the-shell.md)).
  - The quit warning counts active replies and background commands (`apps/desktop/core/src/window/close.rs`).
  - The SSH plugin speaks russh 0.64.1 on ring and keeps one session for each host, with keepalive messages. It opens no pseudo terminal and no shell, and it replaces the host's password in the output that it returns.
  - NFR-PERF-01 to 05 bind on a reference machine, an 8-core Windows 11 desktop with 16 GB, and no requirement covers a low-end laptop.
- Facts of third parties, verified on 2026-10-30:
  - xterm.js (`@xterm/xterm`, MIT): 6.0.0 is the latest stable release, and 6.1 is in beta. Its DOM renderer sets its theme and dimensions as the text of `<style>` elements (`DomRenderer.ts`), which ADR-0004's `style-src 'self'` blocks.
  - ConPTY needs Windows 10 1809 or later. Whether the built-in ConPTY delivers OSC sequences in order with the output is not documented, and Warp reported markers out of order. Microsoft ships a newer ConPTY with Windows Terminal, `conpty.dll` and `OpenConsole.exe`, under MIT.
  - rustix's features `pty` and `termios` and windows-sys's feature `Win32_System_Console` cover pseudo terminals, so no crate for them is needed.
- The spikes of 2026-10-30 on the owner's workstation, Windows 11 build 28000 ([M14 validation results](../roadmap/m14-validation.md)):
  - S1: the built-in ConPTY ran Windows PowerShell 5.1, cmd and Git Bash in a Job Object, kept the markers in order with output of 1, 50 and 3,000 lines, resized, and ended the shell when it closed. A child inherits whether its parent ignores Ctrl+C: started from a process that ignores it, cmd and PowerShell never got Ctrl+C, and `SetConsoleCtrlHandler(NULL, FALSE)` in the parent before the start fixed it. A key's echo took 21.5 ms (p50) in Windows PowerShell and 7.0 ms in Git Bash.
  - S2: on Chromium, the engine of WebView2, under ADR-0004's policy, xterm.js 6.0.0's DOM renderer as shipped broke on 16 blocked inline styles and showed black text on black. The same CSS through a constructable stylesheet rendered correctly, and the WebGL renderer rendered correctly as shipped.
  - S3: vt100 0.18.1 kept every line of real ConPTY sessions and of a flood across scrollback, and its hooks receive the rows that scroll and unknown OSC sequences. alacritty_terminal 0.26 parsed faster and has neither hook.

## Decision

1. The supervisor gets a terminal mode (refines ADR-0014 d1, d5 and d7). `crates/mannie-tools/src/supervisor/terminal.rs` starts an interactive shell attached to a pseudo console and contains its process tree:
   - On Windows, `CreatePseudoConsole` makes the pseudo console. The shell starts suspended with the pseudo console's attribute, goes into a Job Object of its own with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, and then resumes. S1 found that the built-in ConPTY of Windows 11 build 28000 keeps the markers in order with the output, so Mannie uses the built-in ConPTY. If a build that S1 has not checked, such as Windows 10 22H2, reorders or drops markers, Mannie ships Microsoft's ConPTY package beside its program and loads it, and a line of later changes here records that.
   - On Linux, the pseudo terminal comes from rustix. The shell runs in a new session with the pseudo terminal as its controlling terminal, and the child subreaper is set between fork and exec, as for commands.
   - A child inherits whether its parent ignores Ctrl+C, and a shell started from a process that ignores it can never be interrupted (S1). The supervisor clears the flag with `SetConsoleCtrlHandler(NULL, FALSE)` before it starts a shell.
   - The environment is the allow list of commands (ADR-0014 d6), with `TERM=xterm-256color`, `COLORTERM=truecolor` and `TERM_PROGRAM=Mannie`.
   - The shell reads the owner's profile, then the setup that its caller passes, through the shell's own means: `--rcfile` for bash, `ZDOTDIR` for zsh, `--init-command` for fish, `ENV` for sh, `PROMPT` for cmd, and `-NoExit -Command` with the setup's text for PowerShell, since a script file would meet the execution policy. A setup's file lies in Mannie's temporary folder, readable only by the owner's account, and is deleted with its terminal.
   - The mode moves bytes in and out and resizes, with no timeout. Ending a terminal closes the pseudo console, which hangs up the shell, and after a grace of 2 seconds ends what is left of the tree.
   - The mode is built for Windows and Linux, the desktop's platforms (D6). FreeBSD gets it with terminals on workers.
2. The core lists the shells of this machine with their kinds, and starts only a listed shell:
   - On Windows: `powershell.exe` and `cmd.exe` from the system folder; `pwsh.exe` from `%ProgramFiles%\PowerShell\7`, or from an absolute entry of Mannie's `PATH` that lies outside projects and Mannie's folders; and Git's `bash.exe` from `%ProgramFiles%\Git\bin`.
   - On Linux: the account's login shell and the entries of `/etc/shells` that exist.
   - The list comes from checks of files, never from starting a shell.
3. A new extension point, `terminal-hosts` (major 1, ID rule `Owned`), lets a plugin offer hosts where terminals open. The plugin contributes a `TerminalHostSource` with two methods:
   - `hosts()` streams the complete list of its hosts. Each entry has a key, a label, an endpoint, an identity, a state, which is ready or unavailable with a code, and the host's kind of shell when the plugin knows it.
   - `open(OpenTerminal)` opens a terminal on one of the hosts and returns a `TerminalConnection`, which gives `output()`, the bytes and then how the terminal ended, `write`, `resize` and `close(grace)`. For an agent's command, the request carries the endpoint and the identity that the owner authorized, and the plugin refuses a host whose endpoint or key has changed since.

   The runtime consumes the point in its registry of terminals, and the SSH plugin is its first source.

4. A new service, `terminals` (major 1, sensitive), is the core's registry of terminals:
   - `hosts()` streams this machine, with its shells, and the hosts of every source. A `TerminalHostRef` names each one: this machine with one of its shells, or a plugin and its key.
   - `open(TerminalSpec)` takes the conversation, the host, which names the shell on this machine, the folder, the size and the setup. It returns a `Terminal` handle with the connection's methods and `set_running(bool)`. A terminal on this machine starts in the supervisor, and one on a host opens through that host's source. The handle has the shape of the service `local-servers` ([ADR-0043](0043-let-plugins-offer-the-tools-of-tool-servers.md) d5).
   - Every terminal belongs to an existing conversation. A conversation holds at most 8 terminals, and this machine at most 32, those on remote hosts included.
   - A conversation's deletion, the plugin's `release` and quitting Mannie each end the terminals concerned, and the plugin learns of it from how they ended.
5. A command that an agent types into a terminal is an operation with a terminal-command access (refines ADR-0013 d2 and ADR-0034 d6):
   - The SDK's `ToolAccess::TerminalCommand` names the host by its `TerminalHostRef`, the terminal by its number or as a new one, the shell, the command's text, and the state that the terminal last reported: its user and folder. The runtime's adapter resolves the host from the registry, so no plugin names another plugin's endpoint, and adds the acting plugin. The core's `Access::TerminalCommand` carries the resolved label, endpoint and identity.
   - The workspace never allows the access, and full access does ([ADR-0029](0029-let-the-owner-give-conversations-and-hosts-full-access.md)).
   - A grant for the conversation, its project or every conversation, `GrantScope::TerminalCommand`, covers the same command text on the same host: on this machine in the same shell, and on a remote host with the same plugin, target and endpoint.
   - A rule of leading words is limited to its host, and the rules live in a table of their own, `tools_terminal_rules`.
   - Only grants and rules given from a terminal command's approval cover terminal commands, and they cover nothing else (compare D40).
   - A command with metacharacters gets only Allow once and Deny. The request names its own reason, `terminal_command`.
   - An approval covers only the named terminal and its state. When the terminal's user or folder changed before the plugin types, the plugin refuses with `terminal_changed`.
   - On a worker, the ceiling refuses the access with `no_terminals`.
   - The approval names the terminal, the host, the user and the folder, and says that the command runs as typed, in a shell that earlier commands set up.
6. What the owner types reaches the shell as typed, without the policy, as in any terminal (refines ADR-0004 d2, ADR-0013 d1 and ADR-0036 d9):
   - It is not an operation, and it is never logged, stored or shown to a model.
   - The plugin's commands check that the terminal belongs to the conversation, and cap each input at 64 KiB.
   - Opening a terminal on a registered host is the owner's action, and the SSH plugin logs in then, as when it tests a login. An agent's authorized command may also open one (decision 5).
   - [Security](../architecture/security.md) §8 gains a line: script in a compromised webview could type into a terminal or open one. Script that can do that can already turn on full access and send a message (T-60), and the plugin starts off.
7. xterm.js comes through the SDK (D11; refines ADR-0034 d11):
   - The app adds `@xterm/xterm` 6 and the addons `fit`, `search` and `web-links`, pinned. The TypeScript SDK re-exports them as `@mannie/plugin-sdk/terminal`, with the stylesheet bundled from `'self'` and a theme built from Mannie's tokens.
   - Links in output open through `openLink`, which asks the owner first. No clipboard addon loads, so output cannot write to the clipboard.
   - xterm.js loads as a chunk of its own when the first terminal opens, so the app's start and its first bundle do not change.
   - The renderer is chosen automatically: WebGL when the webview reports a WebGL2 context with hardware acceleration; the DOM renderer otherwise, as under SwiftShader, llvmpipe or a virtual machine without a GPU; and the DOM renderer again after a lost context, as on sleep or a switch between GPUs. A setting forces either renderer.
   - The cursor does not blink by default. Smooth scrolling and ligatures stay off, a search marks at most 1,000 matches, and only the last 200 commands keep their marks.
   - The DOM renderer's `<style>` elements break ADR-0004's policy, and the WebGL renderer uses none (S2, on Chromium). No exception to the Content Security Policy is made. The WebGL renderer works as shipped. The DOM renderer, which the automatic choice falls back to without a hardware GPU, gets a recorded `pnpm patch` that moves the text of its two style blocks, `_injectCss` and `_updateDimensions`, into a constructable stylesheet (`adoptedStyleSheets`), which the policy allows. The patch also goes upstream as a pull request. S2 showed that the same CSS through a constructable stylesheet renders correctly.
8. A palette command may have a key (refines ADR-0020 d2):
   - `ShellCommand` gains an optional `keys`, which the shell binds while the command is available.
   - The registry refuses a key that the shell or another command already holds, and the palette shows the key.
   - The terminal plugin's command takes `` Ctrl+` ``, matched by the physical key `Backquote`, so it works on every keyboard layout.
9. The warning before closing or quitting also counts the terminals that are running a command, which the plugin reports through `set_running`. This changes the [window and tray](../features/window-and-tray.md) feature.
10. The threats of [security](../architecture/security.md) gain T-68 to T-73:
    - T-68: script in the webview types into a terminal or opens one (decision 6).
    - T-69: output forges the setup's markers to fake a command's end, its exit code or its output. Every marker carries the terminal's random nonce, and a marker without it is plain output.
    - T-70: a granted command runs in a shell whose aliases, functions, `PATH` or folder earlier commands set. Grants and rules are kept apart, approvals check the terminal's state, and metacharacters get Allow once only.
    - T-71: secrets in a terminal reach the model. Agents read only their own commands' output and what the owner mentions, the SSH plugin replaces the host's password in the stream, and input is never kept.
    - T-72: a command keeps running in a terminal after the owner's attention moved on. The control's count, the quit warning and the ending rules of decision 4 bound it.
    - T-73: output asks the model to run more commands. It is content like any other (T-1).

## Consequences

- Positive: the owner works in terminals beside a conversation, on this machine and on SSH hosts, and agents run commands in the same shells, with the owner's folder, environment and session, under the approvals, grants, rules, full access and journal of every other command. The point and the service serve later sources of hosts, such as the Workers plugin's, and keys serve other palette commands.
- Negative: what the owner types passes no policy, as in any terminal, so script in a compromised webview could type into a terminal (T-68). A granted command runs in a shell whose state earlier commands set (T-70), so the grants and rules of terminal commands stay apart from those of `run_command` and `run_ssh_command`, and a terminal command asks even when a grant or a rule already allows the same text through those tools. The core gains a mode of the supervisor, an access with a table of rules, a point, a service, keys of palette commands and a patched npm package. A terminal keeps its processes running until it ends, which the toolbar's count and the quit warning keep visible.
- Risks: ConPTY varies between Windows builds (R42), the patch of xterm.js drifts from upstream (R43), the owners' shell configurations defeat the setup (R44), the headless emulator differs from xterm.js (R45), the typed setup fails on unusual hosts (R46), and terminals make Mannie lag on low-end laptops (R47), which NFR-PERF-06 to 10 and their suite watch. The cost of the JSON channel for VT output on WebKitGTK is not measured yet (S5); if it breaks the budgets, a binary channel joins this ADR as a line of later changes.

## Alternatives considered

| Option                                                         | Why not chosen                                                                                                                                        |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| portable-pty or another crate for pseudo terminals             | It would start shells outside the supervisor's containment, and rustix and windows-sys already cover pseudo terminals                                 |
| The terminal plugin speaking SSH itself                        | It would read another plugin's hosts and secrets and use russh, which is exclusive to SSH                                                             |
| Agents' commands through `run_command` mirrored into the panel | The owner wants agents to use the same shells, with the owner's folder, environment and SSH session, and the owner to answer their prompts there      |
| Reading the whole terminal for the model                       | The owner chose the agent's own commands and the owner's mentions only (D45)                                                                          |
| A `style-src 'unsafe-inline'` exception                        | It weakens the policy for the whole app, and a patch or the WebGL renderer avoids it                                                                  |
| Terminals shared across conversations, or an activity bar view | The owner chose side panels that belong to a conversation (D45, D18)                                                                                  |
| Microsoft's ConPTY package in every build                      | S1 found that the built-in ConPTY keeps the markers in order, and the package would add a library and a program to every installer without a need yet |

## Validation

M14:

- V4's process tree tests gain the terminal mode on Windows and Linux: ending a terminal and the plugin's release end grandchildren and detached children. Tests of the mode also cover resizing, input and output, and the setup of each kind of shell.
- Policy tests of terminal commands: grants on the same and another host and in the same and another shell, kept apart from `run_command` and `run_ssh_command`, rules limited to their host, metacharacters, full access and a worker's refusal.
- Runtime tests with a fake source of hosts (`crates/mannie-runtime/tests/terminal_commands.rs` and `crates/mannie-runtime/tests/terminals.rs`): the limits, a conversation's deletion, the plugin's release, shutdown and the count of running terminals. Store tests of `tools_terminal_rules` and of the upgrade from the 0.5.0 fixture.
- The injection corpus gains output that asks for commands and output with forged markers, and the planted-credential test gains an SSH terminal.
- S1 on Windows 10 22H2, S2 on WebKitGTK 4.1 with software WebGL, NVDA and Orca, and S5 on the low-end profile ([M14 validation results](../roadmap/m14-validation.md)).
- `task e2e:perf` meets NFR-PERF-06 to 10 on the reference machine and under the low-end profile.
