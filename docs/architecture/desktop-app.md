The desktop app is the master. It is a Tauri 2 application with a Rust core and a SvelteKit UI in the operating system's webview.

## 1. Trust model

The Rust core is trusted, and the webview is not ([ADR-0004](../adr/0004-keep-system-access-in-the-rust-core.md)). The webview renders model output, tool output and file contents, any of which may be hostile. The core therefore treats every command from the webview as untrusted input, validates its arguments, and applies the same policy that applies to a model's request. The webview holds no secrets, no transcripts and no settings that matter.

## 2. IPC contract

| Mechanism | Used for                                                                   | Notes                                                            |
| --------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Commands  | Requests from the UI: send a message, decide an approval, change a setting | Typed arguments, results and errors, generated by tauri-specta   |
| Channels  | Ordered streams from the core: conversation events, run progress           | `tauri::ipc::Channel<T>`, created per subscription with a cursor |
| Events    | Rare broadcasts: a settings change, a worker's status                      | Only for small messages that every window may receive            |

- The types come from `mannie-types`, and the bindings are generated into `apps/desktop/src/lib/generated/` ([ADR-0007](../adr/0007-generate-ipc-bindings-from-rust.md)). The frontend calls only the generated functions.
- Errors are a typed enum with a stable code and its arguments. The UI shows the message for that code from its catalog and never parses error text. The English description in an error is for logs only ([ADR-0019](../adr/0019-keep-visible-text-in-message-catalogs.md)).
- Every command needs a capability grant through `AppManifest::commands`, and only the main window receives grants.

## 3. Streaming to the UI

- The UI subscribes to a conversation by opening a channel with the last sequence number it has, its cursor. The core first sends every stored event after the cursor and then the live events, in order and without gaps.
- The core batches deltas for the UI every 16 to 33 ms, so the frame rate of the webview sets the pace and not the token rate of the provider.
- When the window reloads, the UI subscribes again with the cursor it kept, or from the start if it kept none. Runs never depend on a subscription ([ADR-0012](../adr/0012-run-agents-as-durable-actors.md)).

## 4. Security configuration

- Plugins: single-instance and opener only. The fs, shell and http plugins are not used, and any new plugin needs an ADR.
- `withGlobalTauri` is false, navigation is limited to the app's origin, and the webview cannot open new windows.
- Content Security Policy: `default-src 'self'`; `script-src 'self'`; `style-src 'self'`; `img-src 'self' data: blob:`; `connect-src` limited to Tauri's IPC endpoints; `object-src`, `frame-src` and `base-uri` set to `'none'`. V1 validates the policy with the full component stack.
- `useHttpsScheme` is true and stays true, so the app's origin, and with it the webview's storage, never moves.
- The isolation pattern is not used. [ADR-0004](../adr/0004-keep-system-access-in-the-rust-core.md) explains why.

## 5. Rendering untrusted content

- Model and tool output is rendered as Markdown with raw HTML disabled. Code blocks render as text, with a copy button.
- Images in model output are not loaded from the network. A link is shown as a link; clicking it asks the core, the core shows the full URL to the owner, and the URL opens in the system browser only after the owner confirms.
- File contents and command output render as plain text, never as HTML.
- [M1](../roadmap/milestones.md#m1-chat) proves this with a corpus of hostile Markdown and HTML that must run no script and load nothing remote.

## 6. Frontend structure

```text
apps/desktop/
├── messages/                    # message catalogs, one file per locale; en.json is the base (ADR-0019)
├── project.inlang/              # Paraglide project settings: locales and plugins
├── src/
│   ├── routes/                  # top-level views only; the root layout sets ssr = false, prerender = false
│   └── lib/
│       ├── components/
│       │   ├── ui/              # shadcn-svelte CLI output only (ADR-0006), plus PATCHES.md
│       │   └── app/             # Mannie's shared components, composed from ui/ and bits-ui
│       ├── shell/               # layout and the typed slot registries (extension points)
│       ├── features/<feature>/  # one folder per feature: components, state, slot registrations
│       ├── generated/           # IPC bindings, generated and never committed
│       ├── paraglide/           # message functions compiled from messages/, never committed
│       └── utils/
└── src-tauri/                   # the mannie-desktop crate
```

- State lives in `.svelte.ts` modules that use runes. Each open conversation has a state object that its channel subscription feeds.
- Components are small and do one thing. A view composes feature components through the shell's slots instead of importing features directly.
- Styling uses Tailwind CSS utilities and the theme tokens of shadcn-svelte, without hard-coded colors or per-feature global stylesheets.

## 7. Window and lifecycle

- The single-instance plugin focuses the running window when the app starts a second time, and shows it again if it was hidden in the tray.
- On the first close of the main window, Mannie asks whether to keep running in the system tray or to quit, and saves the answer as a setting that the owner can change later (D13). The [window and tray](../features/window-and-tray.md) feature describes the behavior.
- In tray mode, closing the window only hides it. Runs, channels in the core and worker links continue, and the tray icon's menu opens the window again or quits.
- In quit mode, closing the window quits the app. While runs are active, Mannie warns first, and so does Quit in the tray menu. Quitting interrupts the master's runs, which can be retried. Tasks on workers keep running on their workers.
- The tray icon uses Tauri's `tray-icon` feature, which is part of Tauri itself and not a plugin.
- After the computer resumes from sleep, provider calls that failed while it slept count as transient errors and are retried. The link to each worker reconnects.

## 8. Platform differences

| Topic            | Windows                                               | Linux                                                                                                                                                                                                                                                                           |
| ---------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Webview          | WebView2 Evergreen, updated by Windows                | WebKitGTK 4.1 from the distribution                                                                                                                                                                                                                                             |
| Credential store | Windows Credential Manager                            | Secret Service (GNOME Keyring or KWallet). Without one, credentials cannot be saved (V7).                                                                                                                                                                                       |
| Installer        | NSIS, per user                                        | deb and rpm packages                                                                                                                                                                                                                                                            |
| System tray      | Notification area; clicking the icon opens the window | AppIndicator (libayatana-appindicator on Debian and Ubuntu, libappindicator-gtk3 on Fedora). Clicks on the icon are not delivered, so the menu opens the window. GNOME shows the icon only with the AppIndicator extension; without it, starting Mannie again shows the window. |
| Known issues     | None recorded yet                                     | Some NVIDIA drivers render WebKitGTK incorrectly with DMABUF. The workaround is documented once V1 confirms it.                                                                                                                                                                 |

Each UI change is checked on both webviews before it merges.

## 9. Accessibility

The app meets WCAG 2.1 AA. Every action works from the keyboard, focus is always visible, and automated axe checks run in the end-to-end tests. shadcn-svelte and bits-ui provide the base behavior, and Mannie's own components keep it.

## 10. Languages

The interface is in English, and it is built so that a language can be added without changing code ([ADR-0019](../adr/0019-keep-visible-text-in-message-catalogs.md)):

- Every piece of visible text comes from the message catalogs in `apps/desktop/messages/`, compiled by Paraglide JS into typed message functions. Components contain no literal text, and each feature owns the messages under its key prefix.
- The core sends codes and arguments, never display text. Content (model output, file contents, command output, the owner's own text) is shown as it is.
- Dates, times, numbers and durations are formatted with `Intl` in the current locale.
- The locale is a setting in the core, defaulting to the operating system's language when a catalog exists for it and to English otherwise. A custom Paraglide strategy reads it at startup. Changing it reloads the webview, which does not affect runs.
- The end-to-end tests also run in a pseudo-locale that marks and lengthens every message, so text that bypasses the catalog and layouts that break under longer text are caught.
- Adding a language means adding `messages/<locale>.json` and registering the locale in `project.inlang/`. A check reports keys that a locale is missing.
